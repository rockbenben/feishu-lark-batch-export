# 飞书 / Lark 文档批量导出

> 飞书自带的导出只能一篇一篇点。这个 Chrome 扩展让你在目录树里勾一批，拿到一个 zip。

支持从**知识库**、**云空间**或**一份 URL 列表**批量导出，飞书和 Lark 都能用。可导出 Markdown / Word / PDF，多个文件自动打包，目录结构原样保留。

**图片会一并保存到本地。** 飞书导出的 Markdown 里，图片是带签名的临时链接，约 24 小时后失效；不存下来的话，备份过几天就只剩文字了。

装好后在飞书页面右下角点「批量导出」按钮，面板按 1 → 2 → 3 的顺序操作即可。

<br clear="right">

## 安装

[从 Chrome 应用商店安装](https://chromewebstore.google.com/detail/lomkhccnocgfifghblhfidifhnilcgdi)，点「添加至 Chrome」。**安装前已经打开的飞书标签页需要刷新一次**，扩展不会注入到旧页面。

界面语言默认跟随浏览器，支持中英文，也可以在面板右上角手动切换。

扩展匹配 `*.feishu.cn` 和 `*.larksuite.com`（包括 `xxx.jp.larksuite.com` 这类带区域前缀的子域名），两边的接口和行为经实测一致。私有部署域名（如 `*.larkoffice.com`）未测试；需要的话在 `manifest.json` 的 `matches` 和 `host_permissions` 各加一条，代码不用改，然后按下面的方式手动安装。

### 手动安装（开发者模式）

适用于想看代码、需要改域名，或无法使用商店的情况。[下载最新 zip](https://github.com/rockbenben/feishu-lark-batch-export/releases/latest) 解压，或直接 clone 本仓库，然后：

1. 打开 `chrome://extensions`，右上角开启**开发者模式**。
2. 点**「加载已解压的扩展程序」**，选择包含 `manifest.json` 的目录（zip 解压出来的文件夹，或仓库里的 `extension/`）。
3. 打开任意飞书页面，右下角出现「批量导出」按钮即可。

## 用法

右下角的按钮**可以拖动**，位置会记住。也可以点浏览器工具栏上的扩展图标开合面板。

### 1. 列出文档

选择来源，点「列出文档」。在知识库文档页或文件夹页打开面板时会自动列出，来源也会跟随当前页面自动切换：

- **当前知识库** —— 从当前文档向上找到空间根节点，列出整棵树。需要在 `/wiki/xxx` 页面上。
- **当前文件夹** —— 列出这个文件夹下的全部内容。需要在 `/drive/folder/xxx` 页面上。**别人分享给你的文件夹用这个**，它不在你自己的云空间根目录下，「我的云空间」扫不到。
- **我的云空间** —— 列出你自己云空间根目录下的全部内容，在任何页面都可用。分页会读到服务端返回最后一页为止；分页异常时直接报错，不会把读了一半的结果当成完整列表。
- **URL 列表 TXT** —— 选择一个每行一个链接的 `.txt` 文件。链接必须属于当前打开的飞书 / Lark 站点，支持知识库、新旧版文档、表格、多维表格和附件链接。空行忽略；同一文档的重复链接只保留第一条，查询参数和锚点不影响判重。

URL 列表的几点说明：

- 列出时不逐篇打开网页。普通文档先以 ID 显示，导出成功后文件名改用飞书返回的真实标题；知识库链接需要逐条调接口转换 token，每条间隔 0.4 秒，链接多时会慢一些。
- 附件直链会先读取原文件名，读不到时用 ID 命名。
- 链接不带修改时间，所以「最近改过的」批量勾选对 TXT 来源无效，需要手动勾。
- 页面不存在、没有权限或链接格式错误的条目会在日志里保留对应链接，其余继续处理；如果所有链接都失败，会明确报错。

### 2. 勾选要导出的

勾选目录会**连带勾上它下面的全部文档**；按住 **Alt** 点击则只作用于该条本身。方框里显示一横（半选）表示这条自己没选中，但它下面有选中项，半选本身不参与导出。

导不了的类型（思维笔记）是禁用状态，不能勾选。

「最近改过的」可以一次勾出 7 / 30 / 90 天内改过的文档，适合做增量备份。

### 3. 选格式，导出

多个文件时自动打包为 `飞书导出-YYYY-MM-DD.zip`，只有一个文件就直接下载它，所以不会触发 Chrome「允许下载多个文件」的弹窗。中途点「停止」会中止当前请求，已导出的部分照样打包。

下载单次最多等待 120 秒。网络错误和 HTTP 408 / 429 / 5xx 自动重试，最多两次，间隔 1 秒（响应带 `Retry-After` 时按其等待，最长 30 秒）；401 / 403 / 404 等确定性错误直接记为失败。API 请求单次最多等待 30 秒，导出进度轮询不重试、总计不超过 120 秒。失败只记一条日志并附来源链接。

面板有进度条和按实测速度估算的剩余时间。鼠标悬停日志区域会出现「复制」按钮，有失败记录时常驻，方便反馈问题。「开始导出」固定在面板底部，中间区域独立滚动。

## 设置

在「更多设置」里。默认值的目标是**尽量保真地把知识库镜像到本地**。

| 开关 | 默认 | 说明 |
| --- | --- | --- |
| 一并保存图片 | **开** | 图片链接约 24 小时过期，不保存的话几天后图就全挂了 |
| 保留目录结构 | **开** | 目录层级是知识库里真实的信息，平铺会丢掉它，还会让不同目录下的同名文档撞成 `(2)` |
| 一并保存评论 | 关 | 多数人只要正文；但讨论区经常有正文里没有的结论 |
| 文件名带序号 | 关 | 默认要干净的 `标题.md`。想保留知识库里的排序再开 |
| 文件名带上级目录 | 关 | 目录结构开着时它是冗余的，只在平铺又要消歧时才需要 |
| 文件名带文档唯一 id | **开** | 文件名形如 `标题-doxcnAbC123.md`，和图片目录 `assets/<id>/` 能直接对上 |

设置会记住。序号按目录分别计数：开着「保留目录结构」时每个文件夹各自从 `001` 开始；平铺时才用全局序号。

**保存图片与格式选择相互独立**：只要某篇最终产出的是 `.md`，就把图片抓到 `assets/<文档 id>/001.png` 并把链接改为相对路径，所以选「自动」也照样带图。docx / pdf / xlsx 的图片已内嵌在文件里，这个开关对它们无意义。图片目录按文档 id 隔离，和标题、序号无关：同名文档不会共用目录，同一篇重复导出也落在同一个目录。单张图片 15 秒超时，失败后间隔 1 秒重试，最多两次；仍失败则记一条日志并保留原链接。

## 能导出什么

| 类型 | 格式 |
| --- | --- |
| 文档（新版 / 旧版）| Markdown、Word、PDF |
| 表格 | xlsx |
| 多维表格 | xlsx |
| 附件 | 原文件直接下载 |
| **思维笔记** | **不支持**，见下 |

选的格式当前类型不支持时（比如对表格选 Markdown），会自动退回该类型的默认格式，不会失败。

### 思维笔记为什么不支持

飞书页面菜单里有「下载为 FreeMind（`.mm`）」，但它**没有服务端导出接口**，实测依据：

1. `/space/api/export/create/` 认得 `type=mindnote`，却拒绝 `mm` / `xmind` / `opml` / `txt` 这些扩展名（1018 扩展名不匹配），换成其它类型名一律 1004；`/space/api/mindnote/export/` 之类的独立路径全是 404。
2. 在页面上点一次「下载为 → FreeMind」，抓到的只有权限校验和埋点请求，没有任何导出请求。
3. 思维笔记的内容走实时协作 WebSocket，没有取内容的 HTTP 接口。

也就是说 `.mm` 是前端从内存里的文档模型直接序列化出来的，扩展没有可复用的服务端能力。要支持它得复刻飞书的实时协作协议，那是另一个项目的体量。

## 注意

- **串行导出，每篇间隔 1.5 秒。** 导出在飞书侧是排队任务，并发容易触发限频。几十篇请预留几分钟。这个间隔是保守估计，未实测真实阈值，目前是代码常量而非设置项。
- **打包占内存。** 所有产物先收集再打 zip。内容以 Blob 持有，不进 JS 堆，几百 MB 的批次没问题；不支持 zip64，超出 ZIP32 范围（文件数、大小、偏移）时会明确报错，不会生成损坏的包。zip 用 STORE 不压缩——docx / pdf / xlsx / png 本来就是压缩格式。
- 单篇失败不中断队列，日志记一行，跑完可以点「重试失败的 N 篇」。
- 扩展只用浏览器里已有的登录态调用飞书自己的 Web 接口，**不上传任何数据，没有服务端**。后台脚本只负责转发工具栏点击、读取语言文件，以及为附件直链读取原文件名。详见 [`PRIVACY.md`](PRIVACY.md)。
- 用的是飞书内部接口，飞书改版可能导致失效。接口细节和实测的类型矩阵记在 [`docs/how-it-works.md`](docs/how-it-works.md)，方便对照修。

## 为什么是扩展，不是用户脚本

Chrome 138 起，注入用户脚本需要单独的 **userScripts** 权限，默认关闭。关着时 Tampermonkey 面板一切正常（脚本装着、匹配着、显示运行中），但一行都不执行，也不报错。MV3 的 content script 是扩展核心能力，不受这个开关影响。

## 开发

```bash
node --test test.mjs
```

测试直接读取 `extension/content.js` 源码求值，没有构建步骤，不会出现两份实现漂移。覆盖格式映射、URL 列表解析、导出结果文件名归一、文件名清洗与 id 拼接、日志复制、图片与下载重试、重名处理、树扁平化、空间根定位、手写的 zip 容器、云空间节点归一，以及两份语言文件的一致性（key 集合、占位符个数、代码与 manifest 引用的 key 都存在、界面无写死中文、商店字段不超 Chrome 字符上限）。i18n 测试做过变异验证：故意删 key、去占位符，确认测试会红。

```
extension/
├── manifest.json
├── content.js          # 全部逻辑
├── background.js       # 转发工具栏点击、代读语言文件、读取附件原名
├── panel.css
├── _locales/{zh_CN,en}/messages.json
└── icons/icon-{16,32,48,128}.png
```

这个目录就是发布包：CI 原样打包，不排除任何文件。设计源文件（图标、社交预览图）在 `assets/`。

界面文案走 Chrome 原生的 `chrome.i18n`，扩展名、描述和商店页一起本地化。加一门语言就是在 `_locales/` 下多一个目录，漏 key 或占位符不对测试会报。

### 视觉

图标和社交预览图由 HTML 源文件渲染，改设计只需改源文件再跑一遍命令：

```bash
for n in 16 32 48 128; do
  node ~/.claude/skills/html-shot/render.mjs assets/icon.source.html \
    extension/icons/icon-$n.png --width $n --height $n --transparent
done
node ~/.claude/skills/html-shot/render.mjs assets/social-card.html assets/social-card.png --palette
```

| 项 | 取值 |
| --- | --- |
| 色板 | `#101C22` 墨 · `#1E3440` 石板 · `#E8A33D` 琥珀 · `#C97E1E` 深琥珀 · `#F2EDE4` 纸 |
| 字体 | 标题 Noto Serif SC · 正文 Noto Sans SC · 文件树 Sarasa Fixed SC（CJK 等宽）|

图标画的是面板本身：缩进的勾选行，父节点空框、子节点实心，对应「在树里挑一部分」这件事。琥珀是唯一的信号色，用于已选中状态和 24 小时倒计时；刻意不用飞书的蓝。等宽字体只用在需要对齐的地方（树、文件名、数字、日志）。
