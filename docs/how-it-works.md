# 飞书 / Lark 文档批量导出 — 设计

> 名字里同时写上飞书和 Lark：这工具两边都实测支持，也同时吃知识库和云空间。
> 原名「飞书云文档批量导出」把一半能力藏起来了。「批量导出」几个字保留 ——
> 那是别人真正会去搜的词。

日期：2026-08-04
形态：MV3 Chrome 扩展，单个 content script，无构建步骤

> **2026-08-05 修订**：原定形态是 Tampermonkey 用户脚本。实机验证时发现 Chrome 138 起
> 扩展注入用户脚本需要单独的 **userScripts** 权限且默认关闭 —— 关着时 Tampermonkey
> 显示脚本正在运行，但零执行、零报错、DOM 零痕迹，排查成本极高。改为 MV3 content
> script（属扩展核心功能，不受该开关影响）。逻辑代码一行未改，只是去掉用户脚本头、
> 把内联 CSS 挪进 `panel.css` 交给 manifest 注入。

## 问题

飞书云文档导出只能一个一个点。知识库里几十上百篇文档要备份到本地时，
手工点击不可接受。

## 方案

一个用户脚本，在飞书页面右下角挂一个悬浮面板：扫描当前知识库的完整树，
勾选要导出的节点，按串行队列逐个走飞书自己的 Web 导出接口并触发浏览器下载。

不注入飞书原生侧边栏 —— 那是虚拟滚动的 React 树，注入 checkbox 会被前端改版打碎。
自建面板只依赖后端接口，稳定得多。

## 接口（2026-08-04 在 my.feishu.cn 实测，2026-08-05 在 *.jp.larksuite.com 复验一致）

Lark 侧复验结论：`/space/api/...` 路径、返回结构、虚拟根返回 `code 2`、
图片必须 `withCredentials=false` —— 全部与飞书一致。唯一差异是图床域名带区域后缀
（`internal-api-drive-stream-jp.larksuite.com`），wiki token 也不再有 `wikcn` 前缀
（形如 `<wiki_token>`），`/\/wiki\/([A-Za-z0-9]+)/` 照样能取。


**关键前提：飞书的 `policy-sdk` 劫持了 `window.fetch`，自发的 fetch 一律
`Failed to fetch`。所有请求必须走 `XMLHttpRequest`。**

| 用途 | 请求 |
| --- | --- |
| 节点信息 / 引导 | `GET /space/api/wiki/v2/tree/get_node/?wiki_token={wt}` → `data.space_id`、`data.parent_wiki_token`、`obj_token`、`obj_type`、`title` |
| 子节点 | `GET /space/api/wiki/v2/tree/get_node_child/?space_id={sid}&wiki_token={wt}&expand_shortcut=true&exclude_fields=5&is_pre_heating=false` → `data[wt]` 是节点数组 |
| 建导出任务 | `POST /space/api/export/create/`，头 `x-csrftoken: {_csrf_token cookie}`，体 `{token: obj_token, type, file_extension, event_source:'1', need_comment:false, sub_id:''}` → `data.ticket` |
| 轮询 | `GET /space/api/export/result/{ticket}?token={obj_token}&type={type}` → `data.result.job_status`（`2` 处理中、`0` 成功）、`file_token`、`file_extension` |
| 下载 | `GET /space/api/box/stream/download/all/{file_token}`，同源 |
| 云空间根目录 | `GET /space/api/explorer/v3/my_space/folder/` 和 `/my_space/obj/` —— **文件夹和文档是两个接口**，合起来才是完整的一层 |
| 云空间子目录 | `GET /space/api/explorer/v3/children/list/?token={folderToken}` |
| md 内图片 | md 里是 `![Image](https://internal-api-drive-stream.feishu.cn/space/api/box/stream/download/authcode/?code=…)`。**跨域**，需要 `host_permissions`；**必须 `withCredentials=false`**（带 cookie 会被 CORS 拒）；code 里的 `…_1785871142:1785957542_V3` 是有效期，**约 24 小时**后失效 |

**`x-csrftoken` 必须按 cookie 名精确取。** 飞书页面上同时存在 `passport_csrf_token`
（字节的 passport 用的，跟云文档无关），而 `_csrf_token=` 正好是它的后缀 —— 拿
`document.cookie.match(/_csrf_token=([^;]+)/)` 在整条 cookie 串上找子串会命中它，
把无关的值当成 CSRF token 发出去，`/export/create/` 一律 **403 + 纯文本
`csrf token error`**（不是 JSON，所以连错误码都没有）。

这个 bug 的现象容易误判成权限问题：**文档列得出来、一篇也导不出**。因为列表全是 GET，
不带 `x-csrftoken`，只有建导出任务这一个请求会用到它。`readCookie` 因此是纯函数并由
`test.mjs` 覆盖，回归测试直接用 `passport_csrf_token` 排在前面的真实 cookie 串复现。

顺带：**响应体要带进错误消息**。业务错误是 HTTP 200 + JSON 里的 `code`，能干净捕获；
被网关挡掉时理由只写在那段纯文本里，只报状态码的话权限、CSRF、限频看上去一模一样。

空间根节点：从当前 `wiki_token` 沿 `parent_wiki_token` 一路往上爬到没有父节点为止。

云空间接口的三个坑（2026-08-05 实测）：

- **参数越少越好**。`children/list/` 只带 `token` 返回 200；照抄前端那套
  `type=folder&rank=7&asc=false` 反而 500。
- **`node_list` 才是子项**，`entities.nodes` 里还混着父节点自己（所以 `nodes` 数 = `total` + 1）。
- **节点字段跟知识库不同名**：`name`/`type`/`token` 对应 `title`/`obj_type`/`wiki_token`。
  在 `asNode` 里归一，后面整条流水线不用管来源。`type` 编号跟 `obj_type` 是同一套，
  文件夹是 `0`（子文件夹）或 `4`（空间根）。
- 分页是 `has_more` + `last_label`，实测两页不重叠；游标不前进就跳出，防死循环。

## 类型矩阵（实测）

| obj_type | 名称 | 接口 type | 可用扩展名 |
| --- | --- | --- | --- |
| 2 | 旧版文档 | `doc` | md / docx / pdf |
| 22 | 新版文档 | `docx` | md / docx / pdf |
| 3 | 表格 | `sheet` | xlsx（csv 返回 1018） |
| 8 | 多维表格 | `bitable` | xlsx |
| 11 | 思维笔记 | — | **没有服务端导出接口**，见下 |
| 12 | 附件 | — | 不需要导出任务，`obj_token` 直接走 box 下载 |

错误码：`1018` 扩展名不匹配、`1004` 参数非法。都能干净捕获，队列跳过并记日志。

### 思维笔记：不是接口没找到，是根本没有（2026-08-05 查实）

飞书菜单里确实有「下载为 → FreeMind」。但三条独立证据表明它没有服务端导出：

1. `/export/create/` 认 `type=mindnote` 却拒绝 `mm`/`xmind`/`opml`/`txt`（1018），
   换类型名一律 1004；`mindnote`/`bmn` 的独立路径全 404。
2. 页面上真点一次，只有 `guardian/enforce`（权限）和 `obj_stats/report_operation`
   （埋点，`operate_name: download`）—— 没有任何导出请求。
3. 思维笔记页面根本没有取内容的 REST 接口，内容走实时协作 WebSocket
   （`pandora_ws/ws_ticket` + `rce/messages`）。

结论：`.mm` 由前端从内存模型序列化。要支持就得复刻实时协作协议，超出本项目范围。
面板里对应的行直接禁用，悬停提示说明原因 —— 让人选中一个注定失败的东西更糟。

## 设计要点

- **串行队列**，节点之间 sleep 1.5s，轮询间隔 1s、超时 120s。导出是服务端排队任务，
  并发容易触发限频，省下的时间不值当。
- **产物先收集，收尾统一交付**：>1 个文件打成一个 zip，=1 个直接下。既避开 Chrome
  的「允许下载多个文件」弹窗，也让 md 能带着图片一起走。中途停止则打包已完成的部分。
- **zip 手写 STORE 容器**，不引 JSZip。浏览器没有原生 zip（`CompressionStream` 只有
  deflate，不含容器），无构建步骤下引它就得往仓库塞 ~100KB 的 min.js；而导出物
  docx/pdf/xlsx/png 本身已压缩，STORE 的损失可忽略。约 90 行 + CRC32 查表。
  不支持 zip64（>4GB 或 >65535 个文件会坏）。
- **内容始终以 Blob 形式持有**，只在算 CRC 时读一次 ArrayBuffer 随即丢弃，
  所以几百 MB 的批次不会把 JS 堆撑爆。
- **默认值围绕「尽量保真地镜像知识库」**：图片转本地和保留目录结构默认开
  （前者关掉的代价是隐性的 —— 24 小时后图才挂；后者关掉是主动丢层级信息，
  还会让不同目录下的同名文档撞成 `(2)`）；两个文件名前缀默认关，干净名字优先。
- **序号按目录分别计数**（`nextSeq`）。目录结构关掉时 `dirPrefix` 恒为 `''`，
  自然退化成全局计数；开着时每个文件夹各自从 1 开始 —— 否则文件夹里会出现
  `007`、`019` 这种跳号，序号本来是为了保住顺序，跳号看着倒像是坏了。
- **单文件直下时去掉目录前缀**：`a.download` 不接受路径分隔符，带前缀文件名会被清洗坏。
- **文件名** `序号-父目录-标题.扩展名`，序号和父目录两段各自可关（`buildStem`）。
  非法字符换 `_`，重名加 `(2)`，整体截到 80 字符。
  zip 内除 `assets/` 外不重建目录树 —— 没人要，加起来倒是几乎零成本。
- **图片目录名另走 `safeSlug`**，比文件名多干掉空格、括号、`#?%&`。真实 stem 形如
  `001-✒️Blog 文章发布-✍️文案`，**带空格** —— 直接拿去拼 `![](…)` 会被空格截断，
  渲染器解析不出来，图就是不显示。中文和 emoji 在 md 链接里没问题，不必编码成一串 `%E6`。
- **图片本地化跟格式选择解耦**：判据是「这一篇最终产出的 ext 是不是 md」，
  而不是「用户选没选 Markdown」。所以「自动」模式下文档给 md 时照样带图。
- **树是扁平列表**，靠 depth 缩进渲染，不做折叠。因为 flatten 是深度优先，
  某节点的后代就是它后面「depth 更大」的连续一段（`descendantEnd`），父级 checkbox
  级联因此是一个区间操作，比维护嵌套树状态少一大截代码。
- **级联默认开，Alt + 点击只作用于当前条**。不做「全局级联开关」那种模式切换 ——
  「只要目录本身这篇」和「取消目录但保留子项」都该是单次操作，不该逼用户先切模式再切回来。
- **三态语义定死**：`checked` 永远精确等于「这篇会被导出」，`indeterminate` 只表示
  「自己没选、但后代里有选中的」。两者不混，所以收集选中项的逻辑完全不受影响。
  没有这个提示，Alt 取消父级之后用户看不出子项还勾着。
- **悬浮按钮可拖动、位置记住**。右下角是飞书自己的地盘，而且各页面类型高度不同：
  文档页两个悬浮按钮，表格页因为底部多了状态栏，帮助按钮被顶高一截。挑任何固定
  `bottom` 都只是把碰撞挪到下一种页面类型 —— 96px 在文档页没事，在表格页正好压在
  那个 80x33 的帮助按钮上（实测它占据底部 96–129px，120px 也还压着）。
  默认 150px 是量出来的，剩下的交给拖拽。拖动阈值 4px，手抖不该变成拖拽；
  存位置时要先把整个设置对象读回来再写，否则 `saveSettings` 会把它覆盖掉。
- **面板骨架 = 页眉 + 可滚动中段 + 钉底的操作区**。不是为了好看：flex 子项默认
  `flex-shrink:1`，一旦给固定区域都设成 `flex:none`，面板就有了约 600px 的最小高度，
  而面板是 `overflow:hidden` —— 视口低于约 735px（1366×768 的笔记本去掉浏览器界面
  正好是这个数）时，底部的「开始导出」会被直接裁掉。实测从 600px 一路压到 320px，
  主操作始终可见。**主操作任何时候都不该滚出视线。**
- **报错不套两层前缀**：内层消息本身已经说清发生了什么（`读不到这个节点：…`），
  外面再包一句「没能列出文档：」就会读成两遍「没能……」。日志只记原因，
  而**空白区换成「接下来能试什么」** —— 失败之后那块地方不该还在念通用开场白。
- **过滤只改显示不改状态**：行用 `hidden` 隐藏，checkbox 仍在 DOM 里，
  所以 `checkboxes()` 与 `rows` 的下标对应关系不受影响，勾选逻辑一行都不用动。
  命中项的祖先一并保留，否则筛完只剩一堆没有上下文的孤立标题。
- **图片始终放在 md 同级的 `assets/`**，而不是 zip 顶层。这样 md 里的相对链接跟
  目录深度无关，开不开「保留目录结构」都不必改写成 `../../`。
- **设置存 localStorage**，不用 `chrome.storage`：后者是异步的，为几行状态不值当。
  存坏了或无痕模式下静默退回默认值。
- **文案走 `chrome.i18n` + `_locales`**，不自己搓语言表 —— 只有 `__MSG__` 能把扩展名、
  描述和商店列表页也一起本地化。为此 `TYPES` 存 message key 而不是显示文本，
  `etaSeconds` 只算数不成句，纯函数区因此完全跟语言无关。
- **手动选语言得自己读 messages.json**：`chrome.i18n` 没有运行时覆盖 locale 的 API。
  由 service worker 代读再用消息传回，省掉 `web_accessible_resources`（也就不会把
  语言文件暴露给页面）。**扩展名/描述/工具栏提示切不了**，那是平台限制。
  换语言要重建面板（文案是建面板时一次性写进 DOM 的），所以重建时把展开的树、
  勾选状态、过滤词和日志都接回去 —— 那都是用户的活儿，不能因为换个显示语言就没了。
- **i18n 的失败是静默的**：漏一个 key，英文界面只会露出一个裸 key，不报错不崩。
  所以五条测试守着（key 集合一致、占位符个数一致、引用与声明双向对齐、界面无写死中文、
  商店字段不超 Chrome 的 45/132 字符上限），且都做过变异验证 —— 否则「测试全绿」
  可能只是它们压根没在检查东西。英文描述就是这么被抓到写超了 153 字符的。
- **单个失败不中断**队列，收尾提供「重试失败项」。
- **剩余时间按已完成项的实测均速算**，不用固定的 1.5s×剩余篇数 —— 文档大小差异很大，
  拿常量去乘会离谱。一篇都没完成时不显示，不猜。
- **「按修改时间勾选」是动作不是过滤器**：点一下就把 N 天内改过的勾上，之后随你改。
  所以它不进设置持久化，`fbe-src` 也不进（它该跟着当前页面走，存下来换页后就是错的）。

## 面板的视觉与文案

跟 logo、社交图同一套身份：**墨色的柜子，里面装着纸**。刻意不用飞书蓝 —— 面板是这个
工具唯一属于自己的界面，不该 cosplay 宿主应用。

- **主角是那张装箱单**：标题左对齐等宽，类型右对齐成暗淡的一列。右对齐那一列才是
  让它读起来像「要带走的东西的清单」而不是「文件选择器」的关键。
- **等宽只用在对齐真正有意义的地方**（树、文件名、数字、日志）。页眉和说明用无衬线：
  等宽的中日韩字每字都是全宽，再加字距就散架了。
- **五个开关收进原生 `<details>`**，默认收起。默认值本来就该是对的，多数人不用打开；
  打开时给的是真正的解释，而不是让人猜。
- **重色只给一处**：`开始导出` 用深琥珀，其余全部安静。
- **列表空着时给一句「接下来做什么」**，不是留一片空白；筛不到东西时说清楚筛的是什么。
- **日志要盯十分钟**，所以按正经排版对待，而且没话说的时候不占地方。
- 文案原则：按用户能控制的东西命名（`扫描`→`列出文档`）；按钮说出会发生什么，
  且同一个词贯穿全流程（`开始导出` → `导出完成`）；具体优于笼统
  （`重试失败项` → `重试失败的 3 篇`）；报错说清楚发生了什么，不道歉。

## 不做

- **断点续传**：要持久化已完成集合，还要判断它什么时候失效。而「重试失败项」
  已经覆盖了绝大多数场景，剩下的收益不抵这份复杂度。
- **并发数 / 间隔的旋钮**：1.5s 是拍脑袋定的保守值。正确做法是去实测飞书真实的
  限频阈值，而不是把这个决定甩给用户 —— 加旋钮只是把「我没测」包装成「你可配」。
- 合并成单个 md、Firefox 打包、思维笔记（已实测无可用导出格式）

- 不重建本地目录结构
- 不做增量/断点续传
- 不支持思维笔记（飞书这个接口就是不给）
- 不做飞书私有部署域名（`*.larkoffice.com` 等，未实测；真要支持只需加 match 规则）

## 自检

`pickFormat` / `sanitizeName` / `uniqueName` / `flatten` / `findSpaceRoot` 五个纯函数
由 `test.mjs` 以 `node --test` 断言覆盖。测试直接把 `extension/content.js` 源码读进来用
`new Function` 求值，所以没有构建步骤、也不会出现两份实现漂移。UI 不测。

`findSpaceRoot` 接受一个可注入的 `fetchNode`，因为虚拟根那个 bug 就出在这里 ——
回归测试用假的节点链复现了线上那条 `code 2 InvalidParam`。
